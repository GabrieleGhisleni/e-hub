## Decisions

- TypeScript 7.0.2 (native): `tsc -b` with composite project references works (verified). Base options in `tsconfig.base.json`; `composite` + `emitDeclarationOnly` into `node_modules/.tmp/tsc/`.
- Imports: relative imports in `src/node`, `src/shared`, `test` use explicit `.ts` extensions (`allowImportingTsExtensions`), so tsx, vitest, Vite's config bundler and native Node type stripping all resolve them. Web code uses `@/` (src/web) and `@shared/` (src/shared) aliases, extensionless allowed.
- pnpm 11: `pnpm-workspace.yaml` `allowBuilds: { esbuild: true, sharp: true }` (esbuild postinstall was blocked; sharp 0.35 uses prebuilt `@img/*` binaries, no script). sharp check printed `44`.
- Versions resolved by pnpm's supply-chain policy (minimum release age): vite 8.3.6, @vitejs/plugin-react 6.2.1 (one patch behind latest), react 19.3.1, zod 4.6.7, tailwindcss 4.3.5, vitest 5.1.0, hono 4.13.17, react-router 8.5.1, sharp 0.35.5.
- Fonts: Newsreader (serif, headings) + Inter (sans) via @fontsource-variable.
- shadcn: CLI 4.23 (`shadcn` as devDependency, `pnpm exec shadcn add … -y --overwrite`), style `radix-vega`, base color stone, `radix-ui` unified package. The CLI also installed `cn` (shadcn's clsx+tailwind-merge replacement) and `next-themes`: both removed; components import `cn` from `@/lib/utils` (clsx + tailwind-merge) and `sonner.tsx` uses `src/web/hooks/use-resolved-theme.ts` (follows the `dark` class on <html>), so the theme owner (W3b) only toggles that class. `shadcn/tailwind.css` (custom variants data-open etc. used by the vega components) is imported in index.css, which is why `shadcn` stays a devDependency. Extra files pulled in by the CLI: toggle.tsx (toggle-group dep), input-group.tsx (command dep).
- Tooltip needs `<TooltipProvider>` at the app root (W3b).
- Config shape: `drive` object holds `remote` too (`{remote, root, koboTree, archiveTree, topicSubfolders:{kobo,archive}}`); `cache.dir`; `server.{port,allowedOrigins}`; `site.basePath`. `loadConfig()` is synchronous.
- topics.json is a JSON array; TopicsFileSchema also rejects two labels that map to the same Drive folder name (case-insensitive).
- Starter topics: unsorted (Da smistare), narrativa, saggistica, filosofia.
- Unit tests live in `test/` (not co-located), so src/shared never needs vitest/node imports.

- Naming rules (PLAN §6): NFC; whitespace runs → one space; control/invisible chars removed; `: | / \` → " - " next to a space, "-" between words; `"` → `'`; `? * < >` removed; author ≤ 60 chars; `<author> - <title>` ≤ 120 graphemes and ≤ 200 UTF-8 bytes (word boundary in the second half, dangling punctuation stripped); never starts with "."; fallback "Senza titolo". Topic folders: same sanitizer, ≤ 60 chars / 120 bytes, no trailing dots/spaces, DOS device names get "_", empty → "_".
- `parseDriveFileName` only trusts the `[<id>]` right before `.epub`/`.kepub.epub`, case-insensitive, Crockford alphabet only.
- Test rclone remote: `alias` remote `elibtest` defined in a temp rclone.conf passed via `RCLONE_CONFIG`; inherited `RCLONE_*` env vars are dropped, so `gdrive:`/`elib:` do not exist for test processes (`rclone listremotes` asserted). Verified copyto, lsjson, md5sum, moveto, deletefile.
- `test/helpers/test-env.ts` `createTestEnv()` bundles data dir + cache + remote + config + env for W2b/W3a integration tests.
- Stubs (owners replace): `src/node/server/main.ts` (Hono on 127.0.0.1:port, `GET /api/health`), `src/node/cli/main.ts` (commander, no commands), `src/node/site-data/validate-cli.ts` (validates topics + all books via the repo store, exit 1 on invalid; W2c may extend).

Use `-o <dir>/book.kepub.epub` (explicit name) or an existing output dir. The synthetic EPUB from `makeEpub()` converts fine (koboSpan added).
